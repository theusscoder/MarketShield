# Simulation Engine: How the Pieces Connect

## Data flow

1. `simulator/order_generator.py` creates valid `Order` objects using the shared order contract.
2. `simulator/scenarios.py` declares a fixed set of input orders and expected outcomes.
3. `simulator/runner.py` copies scenario orders, submits them in order to `MatchingEngine`, and collects the resulting `Trade` records.
4. `exchange/matching_engine.py` applies price-time priority and updates order status and remaining quantity.
5. `surveillance/features.py` computes descriptive indicators from the resulting order objects.

The runner copies each order because the matching engine mutates remaining quantity and status. This lets the same scenario be run repeatedly without its input being changed by the previous run.

## Required two-trade scenario

Inputs, with prices shown in rupees for readability:

| Order | Side | Limit price | Quantity |
|---|---|---:|---:|
| S1 | SELL | ₹103 | 6 |
| S2 | SELL | ₹104 | 8 |
| B1 | BUY | ₹105 | 10 |

Expected trades:

| Trade | Buyer | Seller | Execution price | Quantity |
|---|---|---|---:|---:|
| 1 | B1 | S1 | ₹103 | 6 |
| 2 | B1 | S2 | ₹104 | 4 |

Expected final order states:

| Order | Status | Remaining quantity |
|---|---|---:|
| S1 | FILLED | 0 |
| S2 | PARTIALLY_FILLED | 4 |
| B1 | FILLED | 0 |

The total traded quantity is 10. Total trade value is `10300 × 6 + 10400 × 4 = 103400` paise.

## Reproducibility

`generate_orders(seed=..., count=...)` uses a private seeded random generator. Identical seeds and arguments reproduce all generated order fields. Trade IDs are generated by the matching engine and are not used as the definition of business-outcome reproducibility; tests compare buyer, seller, price, quantity, sequence, and final order states.

## Run the tests

From the repository root:

```bash
python -m pytest
```

Surveillance features are indicators for review, not proof of market manipulation.
